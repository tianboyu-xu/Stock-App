# MATR 宏观自适应 Trigger 路由

MATR（Macro-Adaptive Trigger Router）是 Auto Tune 中新增的季度策略入口。
它学习“季初已知的宏观环境 → 本季度现有技术策略的相对效用”，
在 A–F 与 CASH 之间选择本季度参考策略。每个约两周的窗口再在所选代际内调参。

## 使用

1. 在本地 `.env` 配置 `FRED_API_KEY`，重启服务。密钥仅供服务端使用。
2. 打开美股或 ETF 的指标图，运行 Auto Tune；MATR 与其他 Trigger Strategy 一起计算并进入 NAV 对比。
3. 在 Trigger Strategy 中选择 **MATR**，查看本季度参考策略、季初宏观阶段估计、宏观因子、策略排名、相关性、历史季度及双周窗口结果。
4. 建议提供至少 5 年完整日线；模型至少需要 **12 个已完成且数据完整的独立季度**，
   此外还需要技术指标预热历史。较长历史有助于检查关系稳定性，但不保证选型有效。

服务端要求个股与 SPY 均具有 `ADJUSTED_TOTAL_RETURN` 价格标记。
缺失历史版本、交易日历或所需价格数据时，MATR 返回明确状态；已有策略报告仍可使用。
首次历史下载较慢，后续请求复用本地不可覆盖的快照。
宏观数据检查先于技术参数搜索；缺少密钥或历史版本时，不再先执行昂贵的 MATR 调参。
Web 启用 MATR 时复用 ACES 的 15 分钟请求超时，普通不含两者的 API 请求仍为 5 分钟。

API：`GET /api/v1/stocks/{code}/auto-tune?include_macro_router=true`。
新增可选响应字段 `macro_router`；旧请求不运行 MATR，旧缓存缺少该字段时提示重新运行。
Web 的 Auto Tune 请求默认携带该选项，切换当前选择的 Trigger Strategy 不影响是否生成 MATR。
Web 客户端仍使用现有深层 camelCase 转换，例如 `macroRouter.current.selectedStrategy`。
MATR 使用独立的季度验证流程；普通 A–F 的 `window_days`、`test_years`、
训练日期裁剪与 Fine Tune 扫描不改变 MATR 的窗口和验证划分。
请求的 `years` 决定可获得的价格历史长度。

## 配置与存储

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `FRED_API_KEY` | 未配置 | 官方 FRED/ALFRED API 凭证 |
| `MATR_DATA_DIR` | 数据库所在目录下的 `matr/` | 宏观快照与季度选型记录 |
| `MATR_REQUEST_TIMEOUT_SECONDS` | `15` | 单次网络请求超时 |
| `MATR_REQUEST_RETRIES` | `2` | 超时、限流、临时服务错误重试次数 |

默认路径随现有 `DATABASE_PATH` 变化，Docker 应将其所在的数据目录持久化。
这些变量为 `.env` 部署配置，不在 Web 通用设置表单中编辑。
不要将密钥或生成的快照加入版本控制。该能力不增加调度任务，不连接券商下单。

宏观快照位于 `v1/macro_snapshot_YYYYQn.json`，记录观测日期、首个可见版本、
修订版本、原始特征、阶段因子与内容校验值。数据文件原子写入且首次写入后不覆盖。
当前季度选型位于 `decisions/{scope}/YYYYQn.json`，记录训练范围、模型参数、
内层验证结果、排名、快照引用及置信度。
`scope` 区分股票、方法版本和经济/费用设置；在同一设置下重新运行、缩短或扩展历史，
都不会替换已发布的本季度选择。改变费用或经济设置属于独立研究配置。
当前路由方法版本为 **2**，与版本 1 使用不同的选型 `scope`；旧版已冻结的季度记录保留用于审计，
不会被新版重写。宏观数据快照格式仍为 `v1`，可继续复用相同的历史发布数据。
未满足 12 季度要求时不冻结不足样本结果，补足数据后可以重新评估。

历史上曾保存的季度选择会在后续报告中复用。
没有实际保存记录的历史季度标记为 `walk_forward_research`，属于回溯研究，
不宣称当时曾真实发布或执行。当前窗口参数可在新窗口开始时更新，季度策略代际不变。

## 数据可用时间与宏观阶段

对季度 Q，决策日为 Q 开始前最后一个已完成的 NYSE 交易日。
只使用在该日已经可见的 ALFRED 版本；之后发布或修订的数据不能进入该季度特征。
“上季度宏观数据”指截至该时点已公布的最近观测，部分 GDP 等指标可能来自更早季度，
并不等于上一季度最终修订值。日线分析也排除当天尚未收盘的预览 bar。

数据来源遵循 [FRED real-time periods](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)
和 [series observations](https://fred.stlouisfed.org/docs/api/fred/series_observations.html)。
ALFRED 的可用时间精度为日期；本版本不模拟日内发布时刻，不能把这些日期解释为精确到分钟的发布时间。
缺失或过期指标会列在 `missing_features` 中；绝不以今天的修订历史替代 vintage 数据。
FRED JSON 每次最多接受 2,000 个版本日期，长历史按不超过 1,461 天的可用时间段读取，
合并交界处被截断但数值未变的连续版本，避免伪造修订日期。
对官方明确报告没有 ALFRED 版本的区间，按缺失处理；其他网络错误仍返回不可用。
例如 [ICE 高收益债利差](https://fred.stlouisfed.org/series/BAMLH0A0HYM2) 的历史分发范围
自 2026 年 4 月起受限，较早季度可能没有该特征，不以 FRED 当前版本补齐。

首版使用 15 个有明确公开序列的特征：

| 组别 | 特征 / FRED 序列 |
| --- | --- |
| 增长 | 工业生产 3 个月变化 `INDPRO`；零售销售 3 个月变化 `RSXFS`；实际 GDP 季环比 `GDPC1` |
| 劳动力 | 非农总就业 3 个月变化 `PAYEMS`；失业率 3 个月变化 `UNRATE`；初请/续请 4 周均值变化 `ICSA` / `CCSA` |
| 通胀 | 核心 CPI / PCE / 时薪 3 个月年化变化 `CPILFESL` / `PCEPILFE` / `CES0500000003` |
| 利率及信用 | 联邦基金利率变化 `FEDFUNDS`；2Y 利率变化 `DGS2`；10Y 实际利率变化 `DFII10`；2s10s 曲线 `T10Y2Y`；高收益债利差变化 `BAMLH0A0HYM2` |

`RSXFS` 是整体零售和餐饮销售，不冒充 Retail Control Group。
首版不构造没有可靠历史共识数据的 surprise，也不引入已停止公开分发的 ISM 数据。

Growth、Inflation、Labor、Liquidity 因子按固定、公开的变换压缩至 −1～+1。
Growth 表示观测到的增长方向；Inflation 表示当前与前一个三个月通胀速度的差；
Labor 越高表示就业更强；Liquidity 越高表示利率/信用压力缓解。
Growth 与 Inflation 的符号生成阶段估计：

| Growth | Inflation | 阶段 |
| --- | --- | --- |
| 非负 | 非正 | Goldilocks：温和增长 / 通胀回落 |
| 非负 | 正 | Reflation：再通胀 |
| 负 | 非正 | Slowdown：增长放缓 |
| 负 | 正 | Stagflation：滞胀 |

缺少必要因子时阶段为 Unknown。页面显示的是**基于季初信息的本季度阶段估计**，
不是官方周期判定，也不是利用当季后来公布的数据确认的当前状态。

## 双周执行与技术 Auto Tune

复用现有 `strategy_backtester` 的信号、仓位比例、费用、跳空检查和 ATR 退出。
每季度从第一个 NYSE 交易日起切成不重叠的 **10 个交易日**窗口，最后不足 10 天的
尾窗在季度结束后单独结算。现金从每窗开始，收盘信号次日开盘成交。
每窗最多买一次、卖一次；卖出后不能重新进场；窗口结束仍有仓位则收盘强制平仓。
不强制产生交易；CASH 在所有窗口保持零交易。

窗口必须与真实交易日历对齐。缺少个股或 SPY 的一个交易日，就不能将后续日期
挤进同一个“双周窗口”。缺失窗口从训练标签中排除；整季不完整时不进入宏观训练。
当前未完成窗口不提前平仓或计入已实现结果。

每个可调代际使用现有 Auto Tune 搜索预算：48 个固定随机候选加默认参数，共至多 49 个；A 维持默认值。
候选网格和随机种子在读取收益前确定。在窗口开始前，仅使用此前最多 24 个已完成窗口选择该代际参数。
满 24 窗时，按时间将前 18 窗用于拟合、后 6 窗用于验证；先在拟合段保留最多 8 个候选，并加入默认参数作为比较项，
再只用之后的验证段选择参数。历史不足 18 窗时明确使用默认参数；18–23 窗时保留最近 6 窗验证、其余 12–17 窗拟合，
划分日期及选择方法记录在参数诊断中。
不复用普通 Auto Tune 在全局验证集选择出的参数来生成更早季度的标签。
所选代际固定后，两周调参始终局限于该代际。

## 相关性与迭代选型

独立宏观样本单位是季度，不能把一季度的多个窗口当作多个独立宏观样本。
先用 Spearman 相关系数分析宏观特征与“某代际效用减去各代际平均效用”的关系。
这样共同上涨的行情不会被直接误判为某一策略的特殊优势。
相关性至少达到 0.15，且在扩展历史前缀中的方向稳定度至少为 0.75，
才能成为候选特征；最多保留 6 个。全程只在训练前缀计算相关性与标准化参数。

预测组合使用小规模 Ridge 回归与相似历史季度均值。
只比较 4 组明确候选：正则强度 1 / 10、近邻数 3 / 5、预测模型权重 0.7 / 0.4 的
两种组合。内层在最近最多 4 个完整季度验证，外层向前预测下一季度；
特征选择、标准化、模型拟合和误差校准均不使用该季度的标签。
模型选择目标为内层实际所选策略效用的平均值减标准差。
选择规则在内层验证和最终选型中保持一致，包括现金和置信度退避。

版本 2 将是否持有现金与技术代际之间的排名不确定性分开：最佳技术策略的预期效用相对 CASH 的优势
必须超过历史预测误差的 10%，否则选择 CASH；缺少可用特征时也保持现金。
第一名与第二名接近，仅降低对具体代际排名的置信度，不再仅因两个正预期策略接近而全部退回现金。
内层验证与最终选型使用相同规则，并返回 `cash_margin`、`confidence_threshold` 供核对。
置信度是证据分类，不是校准后的获利概率。
效用和相关系数不应显示成预测收益率。

首版使用阶段分类做解释，不额外加入 Markov 转移模型、阶段概率集成或复杂机器学习。
这些扩展只有在独立验证中显示改善后才适合引入。

## 效用、后悔值与报告

复用现有 `EconomicConfig` 与经济奖励入口。
收益扣除现有每边交易成本（费用与滑点的合并近似），再计算：

```text
raw = log(NAV) + benchmark_reward - cagr_hurdle_penalty
      - max_drawdown - max(0, max_drawdown - allowed_max_drawdown)
utility = raw - cash_raw_for_same_interval
```

因此 CASH 的效用精确为 0。收益、SPY 相对表现、最大回撤和长期收益目标共同影响评分；
收益目标按实际时间换算成窗口 hurdle，不将一次双周收益直接年化。
SPY 为调整后的买入持有参考，不参与技术代际路由，也不收取策略换仓成本。
NAV 图及完整季度汇总中的 SPY 使用整个对应区间的调整收盘价比值，连续包含季度边界的隔夜变化。
单季度和单窗口的 SPY 收益仍使用各自起止日期，保持其效用标签含义；这些局部收益连乘不等于连续持有收益。
MATR 收益为税前净费用收益，不复用旧报告中的税后字段。

```text
StrategyRegret = max(当季 A–F 和现金的已实现效用) - 所选策略已实现效用
```

Oracle/后悔值只能事后用于诊断，不参与该季度选择。
报告保留各季度和窗口的选择、训练截止日期、参数、买卖日期及价格、退出原因、
净收益、SPY 收益、预测与实际效用。当前未完成季度可显示已完成窗口的结果，
并进入 NAV 曲线及交易标记，但不会进入宏观训练或样本外完整季度汇总。
汇总明确显示完整季度的起止日期，包含季度胜率、跑赢 SPY 比例、复合收益、最差季度、策略切换次数与平均后悔值。
新增现金季度占比、交易次数、有交易窗口占比、持仓交易日占比，以及 A–F 在相同完整季度、费用和双周执行下的
收益与最大回撤对比，用于区分“路由过度选择现金”和“底层技术策略自身表现不佳”。
持仓交易日取自实际模拟器：开盘即平仓的当日不计入，持仓至收盘的当日计入；此比例不代表按仓位金额加权的平均敞口。

MATR 与其他策略的 NAV 在共有日期区间重新归一化为 1，保留各自实际覆盖范围；共同区间不足时不画虚构对比。
各策略的训练流程仍独立，图中相同日期不意味着它们使用相同训练数据或执行规则。
宏观面板的完整季度累计收益与 NAV 图中的共同区间收益可能不同，应结合标注日期解释。
